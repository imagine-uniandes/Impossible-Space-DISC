## Project

**Impossible Spaces VR** — a Unity 6 (6000.2.8f1, URP) VR experience for Meta Quest 3 demonstrating *change blindness* / *impossible spaces*: the player walks through a virtual maze far larger than the physical 4×4 m guardian, because rooms are swapped around the (mostly stationary) player without them noticing. Puzzle minigames distract the player while the environment changes.

Scripting comments and Inspector tooltips are in **Spanish** — match that language when editing or adding XML doc comments / `[Tooltip]` text.

## Build & Run

This is a GUI-driven Unity project; there is no CLI build script. Development happens inside the Unity Editor.

- **Open:** Unity Hub → Add project from disk → select repo root. Must use Unity **6000.2.8f1** with **Android Build Support** and the **Meta XR All-in-One SDK** (`com.meta.xr.sdk.all` 81.0.0, resolved via `Packages/manifest.json`).
- **Main scene:** `Assets/_Project/Scenes/DISC.unity` (other scenes like `DISC 2`, `pr`, `pruebas` are work-in-progress variants; `Assets/_External/**` scenes are vendor demos — ignore them).
- **Build target:** Android / Quest 3. Deploy the resulting APK via Meta Quest Developer Hub, SideQuest, or `adb install <file>.apk`.
- **Tests:** Unity Test Framework (`com.unity.test-framework`) is present but no test assemblies/files exist yet. Run tests via Window → General → Test Runner in the editor.
- `Assembly-CSharp.csproj` / `.sln` are **auto-generated by Unity** — never hand-edit; they regenerate on focus.

The committed `*.apk` files and `*_BackUpThisFolder_*` directories at the repo root are large build artifacts, not source.

## Architecture: the room-swap system

This is the core of the project. The player perceives a long maze, but rooms are spawned/despawned in place. Three generations of the system coexist under `Scripts/RoomSystems/`:

- **`Legacy/`** (`Room`, `TransitionTrigger`) — original approach, kept for reference.
- **`SpawnBased/`** — the current primary system.
- **`TeleportBased/`** — extends SpawnBased with an intermediate "antechamber" step.

**SpawnBased flow** (`RoomSpawnManager.cs` is the hub):
1. `RoomSpawnManager` holds an ordered `roomPrefabs[]`. On `Start()` → `Initialize()` it spawns `startRoomIndex` and optionally **preloads the next room** inactive (`preloadNextRoom`).
2. Rooms are recycled through `RoomPrefabPool` (`usePool`) to avoid Instantiate/Destroy hitches, or destroyed directly if pooling is off.
3. A door/puzzle completing fires `ObjectToggler.onActionComplete` → `RoomAdvanceNotifier.OnDoorOpened()` (it `FindObjectOfType<RoomSpawnManager>()`) → `AdvanceToNextRoom()`, which swaps the preloaded next room in and releases the previous one.
4. Alternatively, walking into a `SpawnTransitionTrigger` (a trigger collider, activated by `Player`/`Hand` tags) advances directly. The manager auto-wires itself into all `SpawnTransitionTrigger`s of a freshly spawned room via `AssignManagerToSpawnedTriggers` (`autoAssignManagerToSpawnedTriggers`).

**TeleportBased** (`TeleportRoomManager : RoomSpawnManager`) inserts an `antechamberPrefabs[]` stage (index-parallel to `roomPrefabs[]`): door opens → antechamber appears (current room released) → player walks to a center `SpawnTransitionTrigger` → real next room appears. The player never translates; only the environment swaps. See the class header comment for exact per-prefab wiring requirements.

Because triggers/notifiers find the manager via `FindObjectOfType` and managers wire themselves into spawned prefabs at runtime, **most of the gameplay wiring is in the prefabs and the scene, not in code.** A change to spawn behavior usually means editing prefab components + Inspector references, not just `.cs`.

## Minigames

Under `Scripts/Minigames/`, each puzzle is a self-contained manager + interactable pieces, exposing `UnityEvent`s on success that scenes wire to door/room actions (typically `ObjectToggler` → `RoomAdvanceNotifier`):

- **CodePuzzle** — fill 5 slots (object, operator, color, function, boolean). The chosen *color* slot is dynamic and decides which physical key opens the door (no single prefixed answer).
- **SequencePuzzle** — press buttons in a hidden correct order; wrong input auto-resets.
- **LabelMatchPuzzle** — drag labels onto objects; validates only when all slots are filled.

## Utilities

`Scripts/Utilities/ObjectToggler.cs` is the general-purpose glue: enable/disable/destroy target GameObjects, optionally play a door Animator trigger + sound, driven either by UnityEvents (buttons) or trigger colliders. `Scripts/Core/` handles VR camera/player reset (`VRCameraInitialRotation`, `VRPlayerPositionReset`) and the game timer.

## Tooling note

`parse_scene.py` is a standalone helper that parses a Unity `.unity` YAML scene file and dumps GameObjects, components, and MonoBehaviour fields by name (its `targets`/path are hard-coded to a CodePuzzle debugging session). Useful for inspecting scene wiring from outside the editor — adjust the file path and `targets` list before reuse.
